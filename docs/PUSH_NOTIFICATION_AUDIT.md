# Аудит Push-сповіщень (Push Notification Audit)

**Статус:** `VERIFIED` (тексти, deep links, Service Worker `actions`, паралелізація доставки, метрики затримок та фільтрація планувальника у локальній D1 / тестах) | `NOT VERIFIED` (реальна доставка на фізичні пристрої Android / iOS)

---

## 1. Редизайн Push-повідомлень

Для всіх типів сповіщень оновлено формат повідомлень:
- **Заголовок:** єдиний `title: 'Uni Schedule'`.
- **Природні українські тексти (`body`):** адаптовані під сценарії `morning`, `before_lesson`, `before_end`, `evening`, `friday`.
- **Deep links:** перехід на конкретну дату (`/?date=...`) або у вкладку статистики (`/?tab=stats`).
- **Дії в Service Worker (`public/sw.js`):** налаштовано інтерактивні `actions` для швидкої взаємодії зі сповіщенням.

## 2. Вимірювання та оптимізація затримок (Latency)

### 2.1. Стан до оптимізації
- Доставка виконувалася суворо послідовно (цикл `1-by-1`).
- Блокуючі inline-повтори (`150ms + 300ms`) затримували обробку наступних підписок у черзі.
- Використовувалися параметри `TTL: 3600` та `Urgency: normal` для всіх типів сповіщень.
- Відсутня інструментація затримок (неможливо було оцінити `cronLagMs`, час обробки та RTT).
- 5-хвилинне вікно Cron створювало джитер до ~5 хвилин.

### 2.2. Внесені покращення
1. **Метрики та структуроване логування (`CronLatencyMetrics`):**
   - Додано збір `scheduledAt`, `cronStartedAt`, `cronFinishedAt`, `cronLagMs`, `processingMs`, `pushAvgRttMs`.
   - Запроваджено структурований `cron_tick`-лог без персональних даних (non-PII).
2. **Обмежена паралельна доставка:**
   - Впроваджено `MAX_CONCURRENT_DELIVERIES = 10` через `Promise.allSettled`, що усунуло послідовне блокування черги.
3. **Пріоритезація термінових сповіщень:**
   - Для `before_lesson` та `before_end` встановлено `Urgency: high` і `TTL: 900` с.

### 2.3. Зафіксовані бенчмарки (локальна D1)
За результатами `localD1ConstraintsAndCron.test.mjs` (**2/2 PASS**, `5.13s`):
- `processingMs`: **58–104 ms**
- `pushAvgRttMs`: **3–23 ms**

**Залишкова неминуча затримка (`NOT AVOIDABLE` на рівні коду):**
- Гранулярність Cloudflare Cron Trigger становить 5 хвилин на планах Free/Standard Workers.
- Можливий тротлінг push-доставки на рівні операційної системи або браузера кінцевого користувача.

## 3. Фільтрація планувальника за профілем

- Cron-планувальник перед формуванням push-сповіщень фільтрує заняття з урахуванням `subgroup`, `selected_electives` та `selected_track` із профілю користувача.
- Завдяки цьому сповіщення надходять лише за релевантними для конкретного студента парами, без дублювання зайвих ДВВС та інших спеціалізацій.
