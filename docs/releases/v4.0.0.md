# Uni Schedule v4.0.0 — Native Mobile Experience & Academic Profiles

**Дата релізу:** 2026-11-25
**Базовий коміт:** `796d9fb` (v3.6.0)

## Ключові зміни

### Stage A — Плаваюча мобільна навігація (Instagram-inspired)
- `BottomNav.tsx`: ізольована плаваюча капсула (`rounded-full`, ~92% ширини екрана, `max-w-[400px]`, `h-[58px]`, `pb-safe`) на суцільних токенах теми (`bg-surface-elevated`, `border-line`) **без glassmorphism / backdrop-blur**.
- Збережено всі 5 вкладок у поточному порядку з українськими `aria-label`, іконками `25px` (`fill` активна / `regular` неактивна), бейджем дедлайнів та сенсорними цілями `>= 44×44px`.
- Єдиний спільний індикатор `layoutId="mobileNavIndicator"` з пружиною (`stiffness: 420, damping: 30, mass: 0.8`), плавним перельотом між вкладками 1↔5 та підтримкою `prefers-reduced-motion`. Desktop `SidebarNav` не змінювався.

### Stage B — Анімований запуск застосунку
- `AppSplash.tsx`: легкий екран запуску на поточній темі (`bg-canvas`) з іконкою та назвою `Uni Schedule`, без спінерів та glassmorphism.
- Запускається лише 1 раз на холодний старт (не повторюється при перемиканні вкладок або фоновому синку), має жорсткий ліміт часу `1100ms` та поважає `prefers-reduced-motion`.

### Stage C — Нативний скролінг і захист від випадкового зуму
- `index.css` & `index.html`: приховано візуальні браузерні скролбари на мобільних екранах (`max-width: 1023px`) зі збереженням вертикального, горизонтального та momentum-скролу; додано `touch-action: manipulation`, `overflow-x: clip` та `font-size: 16px` на полях вводу на мобільних (запобігає авто-зуму Safari без блокування системної доступності).

### Stage D — Видалення публічного вбудованого розкладу та безпечна міграція
- Прибрано публічну кнопку «Вбудований ФЕП-33с» із налаштувань; нові користувачі більше не отримують `ФЕП-33с` автоматично.
- Існуючі legacy-користувачі `builtin` автоматично й неруйнівно мігрують на живий `ФЕП-33с` щойно доступний онлайн (офлайн-користувачі зберігають доступ без втрати даних); внутрішня `lessonsMap` збережена для резолву 158+ історичних записів відвідуваності.

### Stage E — Підтримка кафедр для живих груп ФЕП-31с–34с
- `src/data/academicProgramRegistry.ts`: data-driven реєстр академічних програм, верифікований за довідником ЛНУ (`ФЕП-31с`, `ФЕП-32с`, `ФЕП-33с`, `ФЕП-34с`) та реальними назвами предметів:
  - `СП` / `ОІТ` → «Нереляційні та розподілені бази даних».
  - `РКС` / `РКТ` → «Вибрані розділи мови програмування С/C».
  - Спільні предмети («Професійний Python», «М'які обчислення» тощо) залишаються видимими для всіх кафедр; невідомі спеціальності не отримують вигаданих кафедр.
- Консистентно працює в денному/тижневому розкладі, `LivePairHero`, статистиці, налаштуваннях, бекапах і push-планувальнику (`workers/api/src/push/scheduler.ts`).

### Stage F — Пошуковий вибір групи з чесною атрибуцією факультетів
- `UniversitySelectorCard.tsx`: доступний `combobox` (`role="combobox"`/`listbox`), відкривається по тапу навіть із порожнім полем, підтримує український пошук, гомогліфи, клавіатуру (`ArrowUp/Down/Enter/Escape`) і перемикач «Шукати серед усіх груп».
- `workers/api/src/routes/universities.ts`: повертає `facultyVerified` та `meta` — підтверджені групи факультету йдуть першими, групи без підтвердженого факультету виділені в окрему секцію, а підтверджені групи *інших* факультетів виключаються.

### Stage G — Онбординг при першому запуску
- `FirstLaunchOnboarding.tsx`: сфокусований екран налаштування для нових (`unconfigured`) користувачів, який повторно використовує `UniversitySelectorCard` і не запускається повторно для вже налаштованих користувачів.

## Необхідні міграції D1
- Нових міграцій D1 для `v4.0.0` **не потрібно** (використовується схема `0001`–`0007` із `v3.6.0`).

## Відомі обмеження
- **Upstream ЛНУ (`n=701&lev=142`):** сервер ЛНУ ігнорує параметр `faculty` в автодоповненні та повертає плаский перелік груп без `facultyId`. Такі групи чесно показуються в окремій секції непідтвердженої атрибуції, доки група не буде синхронізована з явним `facultyId`.
- **iOS Safari / PWA:** системні індикатори прокрутки та жести масштабування на окремих версіях iOS можуть контролюватись ОС незалежно від CSS; фізична перевірка на iPhone PWA виконується окремо після деплою.
