# Синхронізація відвідуваності та точні підсумки — Етап №5

## 1. Схема синхронізації (Offline-First + LWW)

```text
[Пристрій A (PWA)]                         [Cloudflare Worker + D1]                     [Пристрій B (PWA)]
  │                                                   │                                           │
  ├─ 1. Клік «Був» -> миттєво в localStorage          │                                           │
  │     (`uni_schedule_attendance_v1`)                │                                           │
  ├─ 2. Запис у чергу (`..._queue_v1`) з `updatedAt`  │                                           │
  ├─ 3. POST /api/attendance/sync ───────────────────>│                                           │
  │                                       LWW: WHERE excluded.updated_at > existing.updated_at    │
  │                                                   │<── 4. POST /api/attendance/sync ──────────┤
  │                                                   │       (повертає всі зміни > lastSyncAt)   │
  │<── 5. При повторному sync: злиття через LWW ──────┤                                           │
```

### Правила конфліктів і сумісності
- **Первинний ключ у D1:** `(user_id, lesson_id, lesson_date)` — виключає дублікати при повторних sync-запитах.
- **Last-Write-Wins (`updated_at`):** старіший офлайн-запис ніколи не перезапише новіший запис з іншого пристрою.
- **Видалення (зняття відмітки):** передається статус-надгробок (`unmarked`), щоб інший пристрій також видалив відмітку, а не відновив її назад.
- **Старі локальні дані (`uni_schedule_attendance_v1`):** записи без `updatedAt` автоматично мігрують при першій синхронізації без втрат.
- **Невідмічені пари:** ніколи не рахуються як `absent` — у вечірніх та п'ятничних push-підсумках обліковуються окремо як `unmarked` («не відмічено»).

## 2. Інструкція ручного тестування на двох пристроях

1. Запустіть Worker локально (з міграціями `0001`, `0002`, `0003`) і фронтенд із `VITE_API_BASE_URL=http://127.0.0.1:8787`.
2. **Пристрій 1 (напр., Chrome Desktop):** відкрийте сайт, у Налаштуваннях виберіть групу (`ФЕП-33с`) та відмітьте 1 пару як **«Був»**. У `localStorage` автоматично збережеться `uni_schedule_sync_token_v1`.
3. **Прив'язка Пристрою 2 (напр., інший профіль браузера / телефон):** викличте `POST /api/devices/link` із `Authorization: Bearer <token_пристрою_1>` та перенесіть виданий `syncToken` на Пристрій 2 (у майбутньому UI-кнопка прив'язки пристрою).
4. **Перевірка синхронізації:**
   - На Пристрої 2 перезавантажте сторінку — з'явиться відмітка **«Був»** із Пристрою 1.
   - Вимкніть інтернет на Пристрої 1 (`Offline`), змініть статус пари на **«Поважна»** — зміна залишиться в `uni_schedule_attendance_queue_v1`.
   - Увімкніть інтернет — черга автоматично відправиться, і після оновлення сторінки на Пристрої 2 статус оновиться на **«Поважна»**.
   - На Пристрої 2 зніміть відмітку (клік по активній кнопці) — на Пристрої 1 після sync відмітка також зникне (`unmarked`).
