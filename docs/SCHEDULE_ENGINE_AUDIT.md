# Аудит рушія розкладу (Schedule Engine Audit)

**Статус:** `VERIFIED` (парсер, нормалізатор, D1-схема `0005`, фільтрація на клієнті/бекенді та live LNU перевірка для `ФЕП-33с`) | `PARTIALLY VERIFIED` (UI-маркування без фінального результату `verify_app.py`)

---

## 1. Причини появи зайвих дисциплін у групі `ФЕП-33с`

Під час аудиту розкладу групи `ФЕП-33с` (ЛНУ ім. Івана Франка) було виявлено, що в активному розкладі відображалися зайві предмети, які студент не відвідує:

### 1.1. Всі 5 ДВВС відображалися одночасно
У розкладі групи `ФЕП-33с` одночасно з'являлися всі 5 вибіркових дисциплін (ДВВС):
1. `Freelance: робота онлайн`
2. `Інноваційний менеджмент`
3. `Політичний дискурс кіберпанку: ідея та реальність`
4. `Стратегії ефективного інвестування`
5. `Google analytics: інструменти та лайфхаки`

**Кореневі причини:**
- `parseLnuScheduleHtml` не витягував `electiveKey` з HTML-розмітки ЛНУ.
- `useScheduleSource.getLessonsForDate()` обходив `filterLessons()` і перевіряв лише `subgroup`.
- Таблиця `schedule_entries` у Cloudflare D1 не містила колонки `elective_key`.

### 1.2. Нумеровані спеціалізації (треки) відображалися одночасно
Дисципліни різних спеціалізацій, пронумеровані у розкладі ЛНУ (наприклад, `1. М'які обчислення`, `2. Професійний Python`), потрапляли в один потік без фільтрації за обраним треком.

### 1.3. Помилки в парсері, нормалізаторі та статистиці
- `parseSubgroupFromGroupLabel` трактував `subgroup` та `isElective` як взаємовиключні властивості, через що ДВВС із зазначеною підгрупою (або навпаки) класифікувалися некоректно.
- `toAppScheduleBundle` жорстко задавав `weekType: 'both'` замість збереження реальної парності тижня.
- `StatsView` використовував статичний `lessonsMap` замість динамічного `scheduleSource.scheduleMap`, тому статистика відвідуваності не враховувала live-розклад і фільтрацію вибіркових предметів/треків.

## 2. Наскрізне виправлення фільтрації

Фільтрація та модель даних були виправлені по всьому ланцюжку:

```text
parseLnuScheduleHtml -> нормалізатор (toAppScheduleBundle) -> D1 міграція 0005 -> filterLessons -> useScheduleSource -> buildWeekGrid -> StatsView
```

1. **Парсер (`parseLnuScheduleHtml` / `parseSubgroupFromGroupLabel`):**
   - Розділено визначення підгрупи (`1 | 2`) та ознаки вибірковості (`isElective`), вони більше не є взаємовиключними.
   - Реалізовано витягування `electiveKey` (формату `el_<slug>`) та номера треку (`trackNumber`) для нумерованих спеціалізацій.
2. **Нормалізатор (`toAppScheduleBundle`):**
   - Усунено хардкод `weekType: 'both'`; передаються коректні метадані занять (`electiveKey`, `isElective`, `trackNumber`, `subgroup`, `weekType`).
3. **База даних D1 (`0005_schedule_electives.sql`):**
   - Додано підтримку збереження `elective_key` (а також профілів `selected_electives` і `selected_track`).
4. **Доменна логіка (`filterLessons`):**
   - Єдина точка фільтрації за `subgroup`, `selectedElectives` (для `isElective`) та `selectedTrack` (для треків з `trackNumber`).
   - Порожній масив `selectedElectives: []` приховує всі ДВВС, а не показує їх як обов'язкові.
5. **Джерело розкладу (`useScheduleSource`):**
   - `getLessonsForDate()` тепер використовує `filterLessons()` замість ручної перевірки лише `subgroup`.
6. **Сітка тижня (`buildWeekGrid`) та статистика (`StatsView`):**
   - `buildWeekGrid` формує сітку на основі відфільтрованого набору занять.
   - `StatsView` переведено на `scheduleSource.scheduleMap` замість статичного `lessonsMap`.

## 4. Залишкові обмеження

- **Відсутність мапінгу «кафедра → група» в каталозі ЛНУ:** довідник груп ЛНУ (`n=701`) не містить зв'язку між кафедрою/спеціалізацією та групою ні в HTML, ні в JSON.
- **Безпечний ручний вибір:** система не вигадує навчальні плани автоматично; натомість використовується ручний вибір `selectedTrack` та `selectedElectives` користувачем із синхронізацією у профілі.
