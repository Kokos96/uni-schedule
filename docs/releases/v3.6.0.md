# Uni Schedule v3.6.0 — Complete Stabilization Release

**Дата релізу:** 2026-11-25
**Базовий коміт:** `36e093c` (v3.5.2)

## Ключові виправлення

### Stage A — Аварійне відновлення розкладу та профілю
- **D1 FK & Staged Publication (`universities.ts`, міграція `0007_profile_source_revision.sql`):** додано `INSERT OR IGNORE INTO university_groups` перед записом `schedule_entries` (усунуто FK `502` для нових груп) та поетапну публікацію з атомарним перемиканням (помилка під час запису не знищує попередній валідний кеш).
- **Синхронізація профілю та кеш (`useSettings.ts`, `profileSyncQueue.ts`, `scheduleCache.ts`, `useScheduleSource.ts`):** явні режими `source_mode` (`builtin` / `live` / `manual` / `unconfigured`), оптимістичний `revision` проти перезапису новими пристроями, мультигруповий кеш `v3` із міграцією legacy-ключів, `force=1` для ручного оновлення та захист від перемикання на групу з помилковим завантаженням.

### Stage B — Факультети, групи та парсер ЛНУ
- **Гомогліфи та фільтрація факультетів (`lnuParser.ts`, `universities.ts`, `UniversitySelectorCard.tsx`):** нормалізація латинських/кириличних гомогліфів (`ЕКІ-11с` ↔ `ЕКІ-11c`), фільтрація `facultyId` без відсіювання неатрибутованих груп довідника.
- **Надійність парсера ЛНУ (`lnuParser.ts`, `scheduleNormalizer.ts`):** перевірка відповідності групи в заголовку HTML, підтримка рядків практики `<span class="wish_gr_2">` (`ПМІ-31с`), коректна обробка порожньої форми ЛНУ без `502`, виняток для обов'язкових мовних `Збірна група` (`Перша іноземна мова`, `ІНА-34с`), валідація часу та статусу скасованих пар, ID аудиторії з корпусом та опційний поверх.

### Stage C — Відвідуваність, статистика та відновлення бекапів
- **Історичні записи (`attendanceMath.ts`, `StatsView.tsx`):** збереження всіх 158+ історичних записів навіть при порожньому live-розкладі або іншій групі (fallback до `lessonsMap` + категорія «Історичні заняття»).
- **Надійність бекапів та синку (`useAttendance.ts`, `attendanceSync.ts`, `backup.ts`):** `replaceRecords`/`mergeRecords` ставлять мутації у чергу синхронізації, збереження `updatedAt` та профілю без токенів, відкидання застарілого `serverVersion`, детермінований merge за новішим `updatedAt`, серіалізація паралельних синків.

### Stage D — Push-сповіщення, ідентичність пристроїв та Cron
- **Точність сповіщень (`scheduler.ts`, `authDevices.ts`):** `resolveTokenPepper(env)` у `handleRotateToken`, перевірка `covered_from`/`covered_to` для dated-розкладів, `scheduleScope` у `dedupKey`, обчислення дати `mondayIso + day_of_week - 1` для п'ятничного зведення, mid-tick перевірка `revision`/`source_mode`.

### Stage E — PWA, UI та інфраструктура
- **Service Worker (`public/sw.js`):** версія кешу `v9`, явний bypass `/api/`, оновлення `/` при успішній навігації.
- **UI та Worker (`SidebarNav.tsx`, `StatsView.tsx`, `security.ts`, `index.ts`):** українські назви кафедр (`СП`/`ОІТ`/`РКС`/`РКТ`), атомарний D1 rate-limit upsert, перевірка D1 у `/api/health`.

## Відомі обмеження
- **Атрибуція факультетів у довіднику ЛНУ:** публічний ендпоінт `dekanat.lnu.edu.ua` (`n=701&lev=142`) повертає плаский перелік груп без `facultyId`. Групи без відомого факультету залишаються доступними для вибору й не позначаються як підтверджено прив'язані до обраного факультету; прив'язка зберігається лише для груп, синхронізованих із явним `facultyId`.
- **Кафедри та вибіркові дисципліни (ДВВС):** фільтр кафедр (`СП`/`ОІТ`/`РКС`/`РКТ`) застосовується до вбудованого розкладу `ФЕП-33с`. Для live-груп ЛНУ вибіркові предмети визначаються за мітками `ДВВС`/`вибірков`/`Збірна група` (за винятком обов'язкових мовних та фізкультурних збірних груп); якщо сервер ЛНУ не розрізняє трек або підгрупу у HTML, відображаються всі доступні слоти.
- **Фізична перевірка iPhone PWA:** автоматизовані перевірки виконуються у headless Chromium та локальному D1/Miniflare; жива перевірка Push на фізичному iPhone потребує підтвердження після деплою.
