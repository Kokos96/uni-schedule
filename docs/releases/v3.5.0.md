# Release Notes — Uni Schedule `v3.5.0`

## Summary
Uni Schedule `v3.5.0` focuses on timetable reliability, university profile handling, and data consistency across LNU parsing, frontend metadata rendering, exact-date coverage, and backend push scheduling.

## Fixed
- **LNU Parser & HTML Structure (`src/integrations/universities/lnu/htmlStructure.ts`, `lnuParser.ts`, `lnuAdapter.ts`):**
  - Added raw-text handling for `<script>` and `<style>` tags so inline code never mutates the DOM tree, plus self-closing attribute cleanup and inline tag text preservation.
  - Filtered out title/range `<h4>` headings (`Розклад групи ... з DD.MM.YYYY по DD.MM.YYYY`) so empty responses do not falsely succeed; skipped `<thead>`/`<th>` header rows from malformed-row warnings.
  - Switched HTML entity decoding to single-pass replacement (preventing double-decoding).
  - Made parallel-lesson ID disambiguation deterministic across weeks and updated `LNU_DEFAULT_FACULTIES` (23 faculties) + `facultyId` filtering in `getGroups`.
- **University Timetable Normalization (`src/integrations/universities/normalizers/scheduleNormalizer.ts`):**
  - Fixed 1-indexed `DAY_NAMES_UA_FULL[dayNumber]` lookup (previously shifted by 1 day).
  - Stopped inserting placeholder entries (`'Викладача не вказано'`, `'—'`) into `teachersById` and `classroomsById`.
- **Teacher / Classroom Metadata & Day/Week Rendering (`PairCard.tsx`, `WeekGrid.tsx`, `LivePairHero.tsx`, `TeachersList.tsx`, `ClassroomsList.tsx`):**
  - Guarded all schedule and directory views against raw internal IDs (`t_*`, `c_*`) and `'—'`, removed `"Ауд. Аудиторію не вказано"`, prevented `'Викладача'` truncation in `WeekGrid`, and derived `ClassroomsList` building filters dynamically.
- **Date Handling & Cache Isolation (`src/utils/schedule.ts`, `src/hooks/useScheduleSource.ts`):**
  - Fixed `buildWeekGrid` fallback for recurring schedules when `datedLessonsByIso` is empty (`{}`), bypassed `weekParity` filtering on exact-date lessons, distinguished `loaded` / `free_day` / `outside_coverage` / `not_loaded`, bumped cache to `uni_schedule_cached_group_v2` isolated by `(universityId, facultyId, groupId)`, and reset `syncStatus` on profile changes.
- **Academic Profile & Electives (`ProfileSettingsSection.tsx`, `UniversitySelectorCard.tsx`, `SettingsView.tsx`):**
  - Separated academic departments from numbered tracks (`1. М'які обчислення`, `2. Професійний Python` are no longer treated as tracks/departments).
  - Hid static department selectors when live university data lacks department codes, removed hardcoded default group/faculty values (`1005` / `ФЕП-33с`), and preserved saved `selectedElectives` that fall outside the current 18-day fetch window.
- **Backend Timetable & Push Filtering (`workers/api/src/routes/universities.ts`, `workers/api/src/push/scheduler.ts`):**
  - Added `schedule_source_type`, `covered_from`, and `covered_to` persistence/reads, deferred `publishGroupMetadata()` until after `schedule_entries` writes, and aligned `matchesStudentLessonProfile` with `elective_course` fallback, `week_type` parity for recurring lessons, `track_number`, and `cancelled` exclusion.

## Database
- **New Migration:** `workers/api/migrations/0006_schedule_coverage.sql` (adds nullable `schedule_source_type`, `covered_from`, `covered_to` columns to `university_groups`).
- **Deployment Requirement:** Apply `0006_schedule_coverage.sql` to target D1 databases (`--remote`) **before** deploying updated `workers/api` code.

## Known Limitations
- Automatic `СП`/`ОІТ`/`РКС`/`РКТ` department mapping is incomplete for live LNU schedules where upstream HTML exposes only `Спец.потік` / `спец. підгр.` without department codes.
- **«Людина і космос»** was not present in the captured live LNU fixture (`tests/fixtures/lnu-fep33s-2026-11-23-live.html`, 23–29.11.2026); it remains available in the built-in schedule and preserved if previously saved.
- Other LNU faculties/groups beyond the verified fixtures have not yet been exhaustively tested against live upstream responses.
- Physical Android/iOS mobile Web Push delivery was not tested on hardware in this automated environment (`NOT VERIFIED`).
