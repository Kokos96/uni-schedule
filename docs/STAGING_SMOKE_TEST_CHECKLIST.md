# Чекліст Smoke-тестування Staging (Phase F)

> Позначайте кожен пункт фактичним результатом після запуску Staging. Тестові Push-сповіщення надсилати лише на власні тестові пристрої.

## 1. API Health & Інфраструктура (`[ ] Not tested remotely`)
- [ ] `GET <STAGING_WORKER_URL>/api/health` повертає `200` `{ ok: true, service: "uni-schedule-api" }`.
- [ ] CORS дозволяє запити з Vercel Preview URL і блокує сторонні origins (`403 FORBIDDEN_ORIGIN`).
- [ ] `GET /api/push/vapid-public-key` повертає staging `VAPID_PUBLIC_KEY` (відмінний від production).

## 2. Базовий функціонал (Frontend + Staging Worker + LNU) (`[ ] Not tested remotely`)
- [ ] Відкрити Vercel Preview URL у браузері.
- [ ] Обрати університет (ЛНУ) та групу (наприклад, `ФЕП-33с`), дочекатися завантаження розкладу.
- [ ] Перевірити примусове оновлення розкладу та fallback при помилці.
- [ ] Змінити налаштування (підгрупа, тема, вибіркові) і перевірити збереження.
- [ ] Створити, відредагувати й видалити нотатку до пари та дедлайн.

## 3. Attendance Sync (2 окремі браузери / пристрої) (`[ ] Not tested remotely`)
- [ ] Пристрій A відмічає пару (`Був` / `attended`).
- [ ] Пристрій B після синхронізації/перезавантаження бачить `attended`.
- [ ] Пристрій B змінює статус на `Н-ка` (`absent`).
- [ ] Пристрій A отримує `absent`.
- [ ] Пристрій A переходить у режим `Offline`, змінює статус на `Поважна` (`excused`) і перезавантажує PWA.
- [ ] Черга `uni_schedule_attendance_queue_v1` збережена в `localStorage`.
- [ ] Після відновлення мережі черга автоматично синхронізується з Staging D1 і очищується.
- [ ] Застаріла мутація (`stale`) відхиляється (`skippedOlder: 1`), `unmarked` синхронізується коректно.

## 4. Offline PWA (`[ ] Not tested remotely`)
- [ ] Завантажити застосунок онлайн (переконатися, що `sw.js` активний).
- [ ] Вимкнути мережу, перезавантажити сторінку — відкривається кешований розклад та ресурси.
- [ ] Відновити мережу — синхронізація відновлюється без помилок.

## 5. Web Push & Cron на фізичних пристроях (`[ ] Not tested remotely`)
*(Тестувати на Android Chrome PWA та iOS Safari PWA, встановленому на початковий екран)*
- [ ] Дозвіл на сповіщення запитується **лише** після явної дії користувача (не автоматично при завантаженні).
- [ ] Підписка створюється (`POST /api/push/subscriptions`) і зберігається в `uni-schedule-staging-db`.
- [ ] Спрацьовує тестовий Cron-сценарій, сповіщення приходить на пристрій, запис є в `notification_logs`.
- [ ] Повторний Cron tick у межах вікна дедуплікується (дублікат не приходить).
- [ ] Клік по сповіщенню відкриває/фокусує PWA.
- [ ] Вимкнення налаштувань сповіщень або відписка (`DELETE /api/push/subscriptions/:id`) зупиняє доставку.
